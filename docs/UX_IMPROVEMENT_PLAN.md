# CloudBox — план улучшения UX и дизайна

> Стратегический документ: что, зачем и в каком порядке улучшать в интерфейсе CloudBox, чтобы приложение стало «своим» для пользователя, а не просто технически работающим клиентом облака.
>
> Документ дополняет существующие `UI_UX_PLAN.md` (QA-верификация) и `DESIGN_ANALYSIS.md` (аудит визуала). Здесь — продуктовый взгляд: сценарии, боль, решения, приоритеты.

---

## 1. Принципы

1. **Скорость ощущается, а не измеряется.** Пользователь прощает медленную сеть, но не «мёртвый» экран. Любая загрузка должна показывать прогресс, промежуточный результат (превью, постер) и оставаться управляемой (отмена, повтор).
2. **Одно действие — одна точка входа.** Скачивание, просмотр, шаринг должны быть предсказуемо расположены на карточках и в списках; жесты дублируют кнопки, но не заменяют их.
3. **Состояния — это интерфейс.** Пустые папки, ошибки сети, нулевые превью — полноценные экраны с объяснением и действием, а не серые пустоты.
4. **Большой контент — большие элементы управления.** Видео и фото открываются на весь экран с крупными тач-целями (≥48 dp) и автоскрытием хрома.
5. **Уважение к трафику и батарее.** Превью подгружаются дёшево (малые токены), стриминг кэшируется, загрузки возобновляются с обрыва.

## 2. Пользовательские сценарии

### Сценарий A. «Вечер с сериалом на даче» (слабая сеть)
Аня открывает публичную папку на 397 видео через мобильный интернет 3G. Раньше она видела сетку однотипных иконок — невозможно понять, где какая серия. 

**Что уже сделано (эта итерация):** карточки получают постеры кадров (`vxw0`), в плеере — постер до первого кадра, буфер 25–45 с до старта и до 120 с вперёд, кэш 256 МБ: перескок назад не качает заново, позиция воспроизведения запоминается между заходами.

**Что улучшить дальше:**
- Скелетоны-заглушки на месте превью вместо цветных иконок (P1).
- Предзагрузка постера следующего видео в плеере, чтобы листание серий было мгновенным (P2).
- Режим «только аудио» для длинных видео как аварийный вариант при отвратительной связи (P2).

### Сценарий B. «Скачать всё и уйти»
Игорю нужно забрать 40 фотографий с публичной ссылки. Он выделяет файлы долгим тапом, жмёт «Скачать» и закрывает приложение.

**Боль сегодня:** менеджер загрузок без системных уведомлений; при обрыве сети на 200 МБ файле прогресс раньше терялся.

**Что уже сделано:** ретраи с возобновлением по Range, корректная обработка ответа 200 (перезапуск с нуля только если сервер игнорирует диапазон), отзывчивая пауза/отмена.

**Что улучшить дальше:**
- Foreground-уведомление с прогрессом и действиями «Пауза/Отмена» (P0).
- Сводка «папка = N файлов» в очереди: групповые прогресс-бары (P1).
- Экран загрузок: сортировка по статусу/размеру, поиск, «скачать заново» для ошибок (P1).

### Сценарий C. «Вернуться к сохранённой папке»
Мария неделю назад открывала папку «вкуснятина». Она возвращается через список сохранённых ссылок на главном экране.

**Боль сегодня:** карточки сохранённых папок не показывают, что внутри; поиск работает только по названию.

**Что улучшить:**
- Миниатюра-превью папки уже сохраняется (первое изображение с токеном `xw0`) — усилить карточку: счётчик фото/видео, дата последнего открытия (P1).
- «Недавние» и «Избранное» как отдельные секции главного экрана (P1).
- Автообновление счётчика файлов при открытии ссылки (P2).

### Сценарий D. «Отправить другу конкретный файл»
Пётр нашёл нужное видео и хочет скинуть другу прямую ссылку, не объясняя, как искать в папке.

**Что уже сделано:** в плеере и просмотрщике кнопка «Поделиться» отдаёт полную публичную ссылку на сам файл.

**Что улучшить:**
- Добавить «Поделиться» в контекстное меню карточки (долгий тап) (P2).
- Копировать прямую ссылку на скачивание одним тапом (P2).

### Сценарий E. «Странное видео не открывается»
Файл `.avi` с редким кодеком: контейнер поддержан (Media3 AVI-экстрактор), но декодера на устройстве нет.

**Что уже сделано:** понятная панель ошибки с тремя выходами: «Повторить», «Скачать», «Внешний плеер» (передаёт поток VLC/MX Player через `ACTION_VIEW`).

**Что улучшить:**
- Предупреждение заранее на карточке, если расширение экзотическое (P2).
- После скачивания — кнопка «Открыть файл» из уведомления (P1).

## 3. Дизайн-система: ближайшие шаги

| Область | Текущее состояние | Целевое состояние | Приоритет |
|---|---|---|---|
| Цвета | Динамическая палитра Material You + фикс. акценты | Единый токен акцента плеера `PlayerAccent` (уже введён) и вынос остальных хардкодов цвета в `Color.kt` | P1 |
| Типографика | Базовые стили M3 | Явная шкала: заголовок экрана / карточка / метаданные; числовые моно-стили для таймкодов плеера | P1 |
| Отступы | `UiSpacing` (2…32 dp) | Прогнать все экраны: убрать локальные `8.dp`-хардкоды в пользу токенов | P2 |
| Формы карточек | Радиусы 12–14 dp наугад | Токен `UiShapes`: карточка 16 dp, чип 999 dp, панель плеера 20 dp | P2 |
| Иконки статусов | Смешение filled/outlined | Правило: filled = действие доступно, outlined = недоступно/неактивно | P2 |

## 4. Дорожная карта

### P0 — сделать сразу (следующая итерация)
1. **Уведомления загрузок** (сценарий B): foreground service-нотификация с прогрессом, паузой и отменой; канал «Загрузки».
2. **Скелетоны превью** (сценарий A): shimmer-заглушки в сетке, чтобы папка никогда не выглядела «сломанной».
3. **Тяни-обновить (pull-to-refresh)** в проводнике — стандартный жест вместо поиска иконки «Обновить».

### P1 — следующая неделя
4. Переработка карточки сохранённой ссылки (сценарий C): превью + счётчики + дата.
5. Экран загрузок: поиск, сортировка, групповая статистика, «повторить все ошибки».
6. Плеер: предзагрузка постера следующего элемента; кнопка «Следующее видео» рядом с play/pause для папок-сериалов.
7. Типографическая шкала и вынос цветовых хардкодов в токены.

### P2 — по мере роста
8. Режим «только аудио» и фоновое воспроизведение с медиа-нотификацией (Media3 `MediaSessionService`).
9. Контекстные действия карточки (долгий тап): поделиться, копировать ссылку, переименовать локально при скачивании.
10. Пакетные операции над выделением: «выделить первые 50», инвертировать выделение.
11. Тёмная тема плеера — отдельная палитра оверлеев, не зависящая от системной темы.

## 5. Метрики успеха

| Метрика | Сейчас | Цель через 2 итерации |
|---|---|---|
| Время до первого кадра видео (тёплая сеть) | 2–4 с | ≤ 2 с, постер виден мгновенно |
| Доля превью, отрисованных в сетке | 0 % (иконки) | ≥ 95 % за 3 с на 4G |
| Обрывы загрузки, требующие ручного перезапуска | часто | 0 (авторетраи + Range) |
| Возврат к видео «с места остановки» | нет | всегда |
| Оценка «понятно, что делать» (usability-тест, 5 чел.) | — | ≥ 4/5 на каждом экране |

---

## 6. Как проверять изменения

1. Прогонять `UI_UX_PLAN.md` (QA-чеклист) на каждом релизе — он ловит регрессии доступности и адаптивности.
2. Новые экраны прототипировать сначала на Compose-превью (`@Preview`) в двух темах и двух ширинах.
3. Для плеера — чеклист: сеть отвалилась на 10-й минуте, пауза/фон/возврат, вращение экрана, экзотический кодек, папка из 400 файлов.
